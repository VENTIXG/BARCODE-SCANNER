# Εγκατάσταση σε cloud server: πολλοί υπολογιστές, δικό σας domain

Στο τέλος θα έχετε:

- την εφαρμογή στη διεύθυνση π.χ. **https://apothiki.etaireia.gr**, με HTTPS που ανανεώνεται μόνο του,
- όλους τους υπολογιστές (και tablets/κινητά) να βλέπουν **τα ίδια δεδομένα, ζωντανά**,
- **backup κάθε μέρα** και, αν το ρυθμίσετε, **αντίγραφα σε cloud storage**,
- **αυτόματες ενημερώσεις κάθε βράδυ**, με backup πριν από κάθε ενημέρωση και **αυτόματη επιστροφή** στην προηγούμενη έκδοση αν η νέα δεν ξεκινήσει,
- έλεγχο κάθε 5 λεπτά που ξεκινά ξανά την εφαρμογή αν σταματήσει, και αυτόματες ενημερώσεις ασφαλείας του λειτουργικού.

Χρειάζεται μία φορά περίπου 15–20 λεπτά. Μετά δεν χρειάζεται συντήρηση.

---

## Τι χρειάζεστε

| | Τι | Παράδειγμα / κόστος |
|---|---|---|
| 1 | **Server (VPS)** με Ubuntu 24.04 (ή 22.04, Debian 12/13), 2 GB RAM, 20 GB δίσκο, x86 ή ARM | Hetzner, DigitalOcean, Contabo, OVH, Linode κ.ά., περίπου 4–6 €/μήνα |
| 2 | **Domain** ή subdomain | Αν έχετε ήδη domain εταιρείας, ένα subdomain όπως `apothiki.etaireia.gr` δεν κοστίζει τίποτα. Νέο domain περίπου 10 €/χρόνο |
| 3 | *(Προαιρετικό, συνιστάται)* **Cloud storage** για αντίγραφα | Backblaze B2 ή Cloudflare R2 (10 GB δωρεάν), AWS S3, Wasabi |

Αυτά είναι τα μόνα βήματα που χρειάζονται δικό σας λογαριασμό και πληρωμή. Όλα τα υπόλοιπα γίνονται αυτόματα.

---

## Βήμα 1: Ο server

Στον πάροχο φτιάξτε έναν νέο server:

- **Εικόνα:** Ubuntu 24.04
- **Μέγεθος:** 2 GB RAM (1 GB δουλεύει επίσης· ο εγκαταστάτης προσθέτει swap)
- **Firewall του παρόχου** (αν υπάρχει): ανοιχτές οι θύρες **22** (SSH), **80** και **443**

Σημειώστε τη **διεύθυνση IP** του server (π.χ. `203.0.113.25`).

## Βήμα 2: Το domain (DNS)

Στον πάροχο του domain (εκεί που το αγοράσατε, ή στο Cloudflare) προσθέστε μια εγγραφή DNS:

| Τύπος | Όνομα | Τιμή |
|---|---|---|
| `A` | `apothiki` | η IP του server, π.χ. `203.0.113.25` |

Έτσι το `apothiki.etaireia.gr` δείχνει στον server. Στο Cloudflare αφήστε το σύννεφο **γκρι** («DNS only»).
Συνήθως ισχύει σε λίγα λεπτά.

## Βήμα 3: Εγκατάσταση με μία εντολή

**Τρόπος Α, με SSH** (από τα Windows: PowerShell → `ssh root@203.0.113.25`):

```bash
curl -fsSL https://github.com/ventixg/barcode-scanner/releases/latest/download/install.sh | sudo bash
```

Ο εγκαταστάτης ρωτά μόνο τη διεύθυνση (domain). Στο τέλος δείχνει τη διεύθυνση, το όνομα χρήστη `admin`
και έναν **κωδικό**. Σημειώστε τον, γιατί δεν εμφανίζεται ξανά.

**Τρόπος Β, χωρίς SSH:** όταν φτιάχνετε τον server, οι περισσότεροι πάροχοι έχουν πεδίο **«User data» / «Cloud-init»**.
Επικολλήστε εκεί το παρακάτω, με το δικό σας domain και κωδικό (τουλάχιστον 12 χαρακτήρες, λατινικοί, χωρίς το σύμβολο `'`):

```bash
#!/bin/bash
curl -fsSL https://github.com/ventixg/barcode-scanner/releases/latest/download/install.sh | DOMAIN=apothiki.etaireia.gr ADMIN_PASSWORD='Apothiki-Kodikos-2026' bash -s -- --yes
```

Ο server εγκαθιστά τα πάντα μόνος του σε περίπου 5 λεπτά. Μετά φτιάξτε την εγγραφή DNS του βήματος 2 με την IP που
πήρε. Το HTTPS ενεργοποιείται μόλις ισχύσει το DNS.

Τι κάνει ο εγκαταστάτης: Docker, την εφαρμογή, HTTPS (Caddy + Let's Encrypt), daily backup, νυχτερινές ενημερώσεις
(03:30), έλεγχο λειτουργίας ανά 5 λεπτά, ενημερώσεις ασφαλείας Ubuntu (με επανεκκίνηση στις 04:30 μόνο όταν χρειάζεται),
ώρα Ελλάδας στον server (για άλλη ζώνη: `… | sudo TZ=Europe/Nicosia bash`), swap σε μικρούς servers και άνοιγμα των
θυρών 80/443 αν το `ufw` είναι ενεργό.

## Βήμα 4: Πρώτη σύνδεση

1. Ανοίξτε `https://apothiki.etaireia.gr` και συνδεθείτε ως `admin`.
2. **Ρυθμίσεις**: όνομα εταιρείας, νόμισμα.
3. **Χρήστες → Νέος χρήστης**: ένας λογαριασμός για κάθε άτομο. Ρόλοι:
   - *Διαχειριστής*: τα πάντα, μαζί με χρήστες και ρυθμίσεις
   - *Υπεύθυνος*: προϊόντα, απογραφή, διορθώσεις, Excel, αναφορές
   - *Χρήστης αποθήκης*: scanner, εισαγωγή/εξαγωγή, αναζήτηση προϊόντων

   Ο νέος χρήστης αλλάζει τον κωδικό του στην πρώτη σύνδεση.
4. **Ρυθμίσεις → Αντίγραφα ασφαλείας**: φαίνονται τα αντίγραφα. **Ρυθμίσεις → Ενημερώσεις**: η έκδοση και πότε ενημερώθηκε.

## Βήμα 5: Οι υπολογιστές

Σε κάθε υπολογιστή, ένα από τα δύο:

- **Chrome ή Edge**: ανοίξτε τη διεύθυνση. Για εικονίδιο στην επιφάνεια εργασίας και δικό του παράθυρο:
  μενού ⋮ → *Εγκατάσταση εφαρμογής* (Chrome) ή *Εφαρμογές → Εγκατάσταση* (Edge).
- **Εφαρμογή Windows**: κατεβάστε το https://github.com/ventixg/barcode-scanner/releases/latest/download/Warehouse-IMS-Setup.exe,
  εγκαταστήστε το και στην πρώτη οθόνη επιλέξτε **«Server της εταιρείας»**, γράφοντας τη διεύθυνση.
  Η εφαρμογή ενημερώνεται μόνη της.

Barcode scanners USB/Bluetooth (λειτουργία πληκτρολογίου) δουλεύουν χωρίς drivers. Ρυθμίστε τους να στέλνουν
Enter μετά από κάθε κωδικό.

## Αντίγραφα ασφαλείας

- **Κάθε μέρα** γίνεται αντίγραφο ολόκληρης της βάσης στον server (κρατιούνται τα 30 τελευταία) και **πριν από κάθε ενημέρωση**.
- **Αντίγραφα στο cloud** (συνιστάται: αν χαθεί ο server, τα δεδομένα είναι αλλού). Στον server:

  ```bash
  sudo ims offsite
  ```

  Ρωτά endpoint, region, bucket και κλειδιά του παρόχου, κάνει δοκιμή και ανεβάζει το πρώτο αντίγραφο. Από εκεί και πέρα
  κάθε backup ανεβαίνει αυτόματα (αποτυχίες ξαναδοκιμάζονται κάθε 30 λεπτά). Προαιρετικά με **κρυπτογράφηση** (AES-256):
  φυλάξτε τον κωδικό κάπου ασφαλές, χωρίς αυτόν τα αντίγραφα δεν ανοίγουν.

  | Πάροχος | Endpoint | Region |
  |---|---|---|
  | Backblaze B2 | `https://s3.<region>.backblazeb2.com` (φαίνεται στο bucket) | π.χ. `eu-central-003` |
  | Cloudflare R2 | `https://<account-id>.r2.cloudflarestorage.com` | `auto` |
  | AWS S3 | κενό | π.χ. `eu-central-1` |
  | Wasabi | `https://s3.<region>.wasabisys.com` | π.χ. `eu-central-2` |

  Δώστε στα κλειδιά δικαίωμα μόνο σε αυτό το bucket. Η κατάσταση φαίνεται στο **Ρυθμίσεις → Αντίγραφα ασφαλείας → Αντίγραφα στο cloud**
  (δοκιμή σύνδεσης, ανέβασμα τώρα, λίστα, επαναφορά).
- **Επαναφορά:** *Ρυθμίσεις → Αντίγραφα ασφαλείας* (από λίστα, από αρχείο ή από το cloud) ή `sudo ims restore <αρχείο>`. Πριν από κάθε
  επαναφορά φυλάγεται αντίγραφο των τρεχόντων δεδομένων, άρα κάθε επαναφορά αναιρείται.
- **Αν χαθεί ο server:** νέος server → βήματα 1–3 → `sudo ims offsite` με το ίδιο bucket (και τον ίδιο κωδικό κρυπτογράφησης) →
  *Ρυθμίσεις → Αντίγραφα ασφαλείας → Αντίγραφα στο cloud → Επαναφορά* του πιο πρόσφατου. Αλλάξτε την εγγραφή DNS στη νέα IP.

## Ενημερώσεις

- **Αυτόματα κάθε βράδυ** (03:30 ± 15'). Πριν από την ενημέρωση γίνεται backup. Αν η νέα έκδοση δεν απαντήσει σωστά μέσα σε 3 λεπτά,
  ξεκινά ξανά η προηγούμενη. Αν η νέα είχε προλάβει να αναβαθμίσει τη βάση, επανέρχεται και το αντίγραφο, ενώ η αναβαθμισμένη
  βάση φυλάσσεται κι αυτή ως αντίγραφο. Η έκδοση που απέτυχε δεν ξαναδοκιμάζεται αυτόματα.
- Στο **Ρυθμίσεις → Ενημερώσεις** ο διαχειριστής βλέπει έκδοση, τελευταίο έλεγχο και ιστορικό, και έχει το κουμπί
  **«Έλεγχος για ενημέρωση τώρα»**. Η εφαρμογή επανασυνδέεται μόνη της σε περίπου ένα λεπτό.
- Χειροκίνητα: `sudo ims update` (τώρα), `sudo ims rollback` (προηγούμενη έκδοση),
  `sudo ims auto-update off` / `sudo ims auto-update on 02:00`.
- Οι εφαρμογές Windows ελέγχουν κάθε 4 ώρες, κατεβάζουν τη νέα έκδοση στο παρασκήνιο και την εγκαθιστούν στην επόμενη
  επανεκκίνηση (ή αμέσως, αν ο χρήστης το επιλέξει). Αν τρέχουν τοπικά, παίρνουν πρώτα backup.

## Μεταφορά δεδομένων από την εφαρμογή Windows (ένας υπολογιστής) στον server

1. Στην τοπική εφαρμογή: *Ρυθμίσεις → Αντίγραφα ασφαλείας → Backup τώρα*, μετά *Λήψη* του αντιγράφου.
2. Στον server (ως admin): *Ρυθμίσεις → Αντίγραφα ασφαλείας → Επαναφορά από αρχείο…* → το αρχείο `.db`.
3. Στην εφαρμογή Windows: μενού *Σύνδεση → Αλλαγή server…* → «Server της εταιρείας».

Οι χρήστες και οι κωδικοί τους μεταφέρονται μαζί με τα δεδομένα.

## Εντολές στον server

```text
sudo ims status                 έκδοση, κατάσταση, backups, ενημερώσεις, χώρος δίσκου
sudo ims update                 ενημέρωση τώρα (με backup και αυτόματη επιστροφή)
sudo ims rollback               επιστροφή στην προηγούμενη έκδοση
sudo ims backup                 backup τώρα
sudo ims restore <αρχείο>       επαναφορά (κρατά αντίγραφο των τρεχόντων)
sudo ims reset-password admin   νέος προσωρινός κωδικός (π.χ. αν ξεχάσατε τον κωδικό του admin)
sudo ims offsite                ρύθμιση αντιγράφων στο cloud
sudo ims auto-update on|off     νυχτερινές ενημερώσεις
sudo ims logs                   μηνύματα της εφαρμογής
sudo ims start | stop | restart
```

Αρχεία: `/opt/warehouse-ims/.env` (ρυθμίσεις, μόνο για root), `/opt/warehouse-ims/data` (βάση, φωτογραφίες, backups),
`/opt/warehouse-ims/state` (κατάσταση ενημερώσεων).

## Ασφάλεια

- Μόνο οι θύρες 80/443 είναι ανοιχτές για την εφαρμογή. Η βάση δεν είναι προσβάσιμη απ' έξω.
- HTTPS με πιστοποιητικό Let's Encrypt που ανανεώνεται αυτόματα. HSTS. Cookies `Secure`, `HttpOnly`, `SameSite=Strict`.
- Κωδικοί αποθηκευμένοι με bcrypt. Όριο προσπαθειών σύνδεσης. Δικαιώματα ελέγχονται στον server για κάθε αίτημα.
- Το `.env` (μυστικό κλειδί συνεδριών, κλειδιά cloud) διαβάζεται μόνο από τον root. Ο αρχικός κωδικός του admin
  σβήνεται από το `.env` μετά την πρώτη εκκίνηση.
- Κάθε έκδοση κατεβαίνει από τις GitHub Releases και ελέγχεται με SHA-256 πριν εγκατασταθεί.
- Ενημερώσεις ασφαλείας του Ubuntu εφαρμόζονται αυτόματα.

## Αν κάτι δεν δουλεύει

| Πρόβλημα | Λύση |
|---|---|
| Η διεύθυνση δεν ανοίγει ή δείχνει σφάλμα πιστοποιητικού | Ελέγξτε ότι η εγγραφή A δείχνει στην IP του server (`ping apothiki.etaireia.gr`) και ότι οι θύρες 80/443 είναι ανοιχτές στο firewall του παρόχου. Το πιστοποιητικό εκδίδεται μόνο του μόλις ισχύσουν και τα δύο (μπορεί να αργήσει έως μία ώρα αν το DNS φτιάχτηκε μετά την εγκατάσταση· για άμεση νέα προσπάθεια: `sudo ims restart`). |
| Ξεχάσατε τον κωδικό του admin | `sudo ims reset-password admin` |
| «Εκτός σύνδεσης» σε όλους τους υπολογιστές | `sudo ims status` και `sudo ims logs`. Συνήθως ο έλεγχος των 5 λεπτών την ξεκινά μόνος του. |
| Μια ενημέρωση απέτυχε | Έγινε ήδη αυτόματη επιστροφή, φαίνεται στο *Ρυθμίσεις → Ενημερώσεις*. Η επόμενη διορθωμένη έκδοση εγκαθίσταται κανονικά. |
| Λίγος χώρος στον δίσκο | Φαίνεται στο *Ρυθμίσεις → Ενημερώσεις*. Μειώστε το «Διατήρηση τελευταίων» στα αντίγραφα ασφαλείας ή μεγαλώστε τον δίσκο. |

## Τοπικό δίκτυο γραφείου χωρίς domain

Μόνο για κλειστό δίκτυο, χωρίς πρόσβαση από internet (χωρίς HTTPS):

```bash
curl -fsSL https://github.com/ventixg/barcode-scanner/releases/latest/download/install.sh | sudo bash -s -- --lan
```

Οι υπολογιστές ανοίγουν `http://<IP-του-server>`.

## Για προγραμματιστές

- **Νέα έκδοση:** `npm run version:patch` (ή `version:minor`), commit, push στο κύριο branch. Το workflow *Release* τρέχει όλα
  τα τεστ, φτιάχνει images (x86_64/arm64), τον installer Windows και ένα τεστ αυτόματης ενημέρωσης σε Windows, και δημοσιεύει
  τη GitHub Release `v<έκδοση>`. Από εκεί την παίρνουν μόνοι τους servers και εφαρμογές.
- **Τεστ όλου του κύκλου του server** (εγκατάσταση, ενημέρωση, αποτυχημένη ενημέρωση με επιστροφή, backup, επαναφορά):
  `sudo -E deploy/test/lifecycle.sh` (χρειάζεται Docker).
- **Χτίσιμο από τον κώδικα** (δοκιμές/staging): `cp .env.example .env`, συμπληρώστε, `docker compose up -d --build`.
- Αρχεία: `deploy/install.sh` (εγκαταστάτης), `deploy/server/` (compose, Caddy, εργαλείο `ims`, μονάδες systemd),
  `deploy/build-release.sh` (αρχεία έκδοσης).
- Τα αρχεία μιας έκδοσης στις Releases: `VERSION`, `install.sh`, `ims-server.tar.gz`, `ims-image-amd64.tar.gz`,
  `ims-image-arm64.tar.gz`, `Warehouse-IMS-Setup.exe`, `latest.yml`, `SHA256SUMS`.
