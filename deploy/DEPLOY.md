# Εγκατάσταση σε server (Docker) και αναβαθμίσεις

Αυτός ο οδηγός αφορά τη **λειτουργία server**: μία εφαρμογή σε έναν κεντρικό server (VPS
ή server του γραφείου), και όλοι οι υπολογιστές συνδέονται από τον browser. Οι
ενημερώσεις γίνονται μία φορά στον server και ισχύουν για όλους.

Για έναν μόνο υπολογιστή αρκεί ο Windows installer (βλ. README).

---

## 1. Τι χρειάζεστε

- Ένα Linux server (VPS ή μηχάνημα του γραφείου) με **Docker** και **Docker Compose** (v2).
- Για πρόσβαση από το internet: ένα **domain** (π.χ. `ims.mycompany.gr`) με εγγραφή **A** προς
  τη διεύθυνση του server, και ανοιχτές τις θύρες **80** και **443**.
- Για πρόσβαση μόνο μέσα στο γραφείο: δεν χρειάζεται domain (βλ. §5).

## 2. Εγκατάσταση

```bash
git clone https://github.com/VENTIXG/BARCODE-SCANNER.git ims
cd ims
git checkout v1.1.0          # η έκδοση που θέλετε (ή το main)
cp .env.example .env
```

Ανοίξτε το `.env` και συμπληρώστε:

| Μεταβλητή | Τι βάζετε |
|---|---|
| `DOMAIN` | η διεύθυνση, π.χ. `ims.mycompany.gr` |
| `COOKIE_SECURE` | `true` με HTTPS (προεπιλογή) |
| `JWT_SECRET` | μεγάλη τυχαία συμβολοσειρά: `openssl rand -hex 48` |
| `ADMIN_PASSWORD` | κωδικός του πρώτου διαχειριστή, τουλάχιστον 12 χαρακτήρες |

Μετά:

```bash
docker compose up -d --build
docker compose ps             # το app πρέπει να είναι "healthy"
```

Η πρώτη εκκίνηση δημιουργεί τη βάση και τον χρήστη `admin` με τον κωδικό του `ADMIN_PASSWORD`.
Ο server **δεν ξεκινά** χωρίς αυτόν τον κωδικό ή με αδύναμο κωδικό, και **δεν τυπώνει** τον κωδικό στα logs.

Ανοίξτε `https://ims.mycompany.gr`, συνδεθείτε ως `admin` και:
1. **Χρήστες → Νέος χρήστης** για κάθε άτομο του προσωπικού (ρόλος: Διαχειριστής, Υπεύθυνος ή Χρήστης αποθήκης).
   Ο νέος χρήστης αλλάζει τον κωδικό του στην πρώτη σύνδεση.
2. Κρατήστε τον κωδικό του `admin` μόνο για έκτακτη ανάγκη.

Το HTTPS (πιστοποιητικό Let's Encrypt) το αναλαμβάνει ο Caddy αυτόματα. Χρειάζεται να
είναι σωστή η εγγραφή DNS και ανοιχτές οι θύρες 80 και 443.

## 3. Πρόσβαση από άλλους υπολογιστές

Κάθε υπολογιστής ανοίγει τη διεύθυνση στον browser (Chrome, Edge, Firefox):
- `https://ims.mycompany.gr` (από παντού, με HTTPS), ή
- `http://<IP του server>` (μόνο στο δίκτυο του γραφείου, βλ. §5).

Συνδέεται με το **δικό του** username και κωδικό, από όποιον υπολογιστή θέλει. Τα δεδομένα είναι
ένα κοινό σύνολο: ό,τι γίνεται σε έναν υπολογιστή εμφανίζεται σε όλους **αμέσως**, χωρίς
ανανέωση της σελίδας. Η ένδειξη **Ζωντανά** στην κορυφή δείχνει ότι η σύνδεση είναι ενεργή.
Αν χαθεί το δίκτυο, η ένδειξη γίνεται «Επανασύνδεση…» και η σύνδεση ξαναδένει μόνη της.

Για τα barcode scanner: USB ή Bluetooth σε λειτουργία πληκτρολογίου (HID), με Enter μετά από κάθε κωδικό.
Δουλεύουν σε κάθε υπολογιστή χωρίς εγκατάσταση.

## 4. Αντίγραφα ασφαλείας

Αυτόματα:
- κάθε μέρα, και όταν χρειάζεται πριν κλείσει ο server, γίνεται αντίγραφο της βάσης
  στον φάκελο `backups` του τόμου δεδομένων (τα τελευταία 30 κρατιούνται).

Χειροκίνητα:
- **Ρυθμίσεις → Αντίγραφα ασφαλείας → Backup τώρα** (ή λήψη αρχείου `.db` στον υπολογιστή σας).

Εκτός server (**συνιστάται**): τα αντίγραφα μένουν στον ίδιο server. Αντιγράψτε τον φάκελο
`backups` αλλού τουλάχιστον μία φορά την εβδομάδα:

```bash
docker compose exec -T app tar czf - -C /data backups > ims-backups-$(date +%F).tgz
```

**Επαναφορά:** **Ρυθμίσεις → Αντίγραφα ασφαλείας → ↺** στο αρχείο που θέλετε, ή
«Επαναφορά από αρχείο». Πριν από κάθε επαναφορά κρατείται αντίγραφο της τρέχουσας
κατάστασης, άρα μπορείτε να την αναιρέσετε. Όλοι οι χρήστες αποσυνδέονται.

**Έλεγχος ότι η επαναφορά δουλεύει:** μία φορά τον χρόνο, επαναφέρετε ένα αντίγραφο σε
δοκιμαστικό stack (§7) και ελέγχετε ότι τα αποθέματα είναι σωστά.

## 5. Χωρίς domain (μόνο γραφείο)

Στο `.env`:
```
DOMAIN=:80
COOKIE_SECURE=false
```
και `docker compose up -d`. Η εφαρμογή είναι προσβάσιμη στο `http://<IP του server>`.
Χωρίς HTTPS τα δεδομένα κυκλοφορούν χωρίς κρυπτογράφηση: κρατήστε το δίκτυο κλειστό
(χωρίς πρόσβαση από το internet).

## 6. Αναβάθμιση και επαναφορά προηγούμενης έκδοσης

Κάθε έκδοση είναι ένα tag (`v1.1.0`, `v1.2.0`…) στο GitHub.

```bash
deploy/update.sh v1.2.0       # αναβάθμιση
deploy/update.sh --rollback   # επιστροφή στην προηγούμενη έκδοση
```

Τι κάνει η αναβάθμιση:
1. Αντίγραφο της βάσης στον τόμο `backups`.
2. Checkout της έκδοσης και build της εικόνας.
3. Επανεκκίνηση. Η εφαρμογή κρατά αντίγραφο πριν εφαρμόσει τυχόν νέες αλλαγές στη βάση.
4. Αναμονή μέχρι το `/api/health` να απαντά με τη νέα έκδοση.

Αν κάποιο βήμα αποτύχει, ξαναξεκινά αυτόματα η προηγούμενη έκδοση. Η βάση επαναφέρεται από το
αντίγραφο μόνο αν η αναβάθμιση την είχε αλλάξει. Τα δεδομένα που καταχωρήθηκαν ανάμεσα στο
αντίγραφο και στο rollback χάνονται, γι' αυτό τρέχετε αναβαθμίσεις όταν δεν δουλεύει κανείς.

Οι βάσεις δεδομένων **δεν έχουν destructive migrations**: οι αλλαγές προσθέτουν στήλες και
πίνακες, δεν διαγράφουν δεδομένα. Οι χρήστες βλέπουν τη νέα έκδοση μετά από ανανέωση της
σελίδας· ανοιχτοί browsers ενημερώνονται με μήνυμα.

## 7. Δοκιμαστικό περιβάλλον (staging)

Ένα δεύτερο, ανεξάρτητο stack με δικό του `.env` (άλλο domain, άλλες θύρες, άλλη βάση):

```bash
cp .env.example .env.staging          # DOMAIN=staging.ims.mycompany.gr, HTTP_PORT=8080, HTTPS_PORT=8443
docker compose -p ims-staging --env-file .env.staging up -d --build
```

Δοκιμάζετε εκεί κάθε νέα έκδοση πριν την παραγωγή. Η παραγωγή και το staging έχουν
διαφορετικούς τόμους δεδομένων (`ims-staging_ims-data`), άρα δεν μπλέκονται.

## 8. Έλεγχοι λειτουργίας

```bash
docker compose ps                             # healthy
docker compose logs --tail=50 app             # σφάλματα εκκίνησης
curl -s https://ims.mycompany.gr/api/health   # {"ok":true,"version":"..."}
```

## 9. Τι δεν καλύπτει αυτός ο οδηγός

- **Υπογραφή κώδικα** του Windows installer (SmartScreen).
- **Επαναφορά κωδικού μέσω email**: η επαναφορά γίνεται από τον διαχειριστή, που δίνει προσωρινό κωδικό.
- **Περισσότερους του ενός server** για το ίδιο αρχείο δεδομένων (ένας server ανά βάση).
- **PostgreSQL**: η βάση είναι SQLite, σε τόμο Docker στον server.
